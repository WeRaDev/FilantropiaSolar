# FilantropiaSolar for Nextcloud

Solar energy management for Nextcloud. Monitor PV installations across
Portugal, visualize production and weather, get ML-backed production
estimates, and track savings against grid electricity prices.

**Current version: 3.2.26** (see [CHANGELOG.md](CHANGELOG.md) and `appinfo/info.xml`)

## Features

- **Interactive map** — Leaflet map with lifecycle-aware markers (ops fleet +
  virtuals); location pin fixed for edit-on-map
- **Analytics modal** — Historical (NC series SoT) and Predicted modes;
  Europe/Lisbon hour buckets; Day/Week/Month/Year; weather layers; View data;
  export to computer or Nextcloud Files; measured CSV upload (modal stacks above analysis)
- **Hourly series** — `oc_fs_readings` with `provenance` (`measured` immutable over
  `simulated`); `SeriesRollForwardJob` (1h) and chunked `SeriesBackfillJob`
- **ML-backed predictions** — ensemble models on Mendeley corpus; ops stations
  use capacity/coords + simulate path; production accuracy verifier vs PVGIS
- **Lifecycle** — virtual / planned / running (+ soft-remove); admin actions;
  bearer lifecycle API for Odoo CRM mirror
- **Virtual installations** — custom stations with optional historical upload
- **Admin dashboard** — dataset/ops management, ML cache/train, FilantropiaSolarAdmin ACL
- **Public read-only API** — Planned + Running only (no virtual/dataset leak);
  stations/dashboard/estimate for Odoo public site
- **Odoo addon (19.0.2.22.0)** — public map, candidatura → CRM, queue_job stage
  mirror, grid_connection_type, NC Stations import/reconcile
- **Savings / grid** — on-grid vs off-grid factors; configurable grid price
- **Weather sources** — Open-Meteo, historical files, synthetic (traced in UI)
- **Multi-language** — English and Portuguese

## Platform architecture

| Service | Container | Port | Role |
|---|---|---|---|
| Nextcloud 28 (Apache) | `filantropia-nextcloud` | 8080 (TRL5: 18080) | App host (`custom_apps/filantropia_solar`) |
| MariaDB 10.11 | `filantropia-db` | 3306 | Canonical station store (Nextcloud DB) |
| Redis 7 | `filantropia-redis` | — | Cache |
| ML microservice (FastAPI) | `filantropia-ml` | 8501 | Training, estimates, dashboard cache |
| Odoo 19 (profile `odoo`) | `filantropia-odoo` | 8069 | Public website + CRM (optional) |
| Adminer (profile `debug`) | `filantropia-adminer` | 8081 | DB inspection (optional) |

The ML service loads the Mendeley dataset from `../Data` and weather files
from `../weather_files` (mounted read-only).

## Quick start (development stack)

```bash
# One-command bring-up: stack, Nextcloud config, app enable, public API
# token, dataset import, ML training (idempotent, safe to re-run)
bash scripts/setup.sh

# Afterwards
#   Nextcloud:   http://localhost:8080  (admin / admin)
#   ML service:  http://localhost:8501  (docs at /docs)
```

Optional Odoo public site:

```bash
export FS_PUBLIC_API_TOKEN=$(cat ../../SolarSeed-v3/.secrets/filantropia_public_api_token)
docker compose --profile odoo up -d --build
#   Public site: http://localhost:8069/filantropia-solar
```

After an app version bump, apply migrations:

```bash
docker exec -u 33 filantropia-nextcloud php occ upgrade
```

## TRL4 / TRL5 deployment

**TRL4** — join SolarSeed-v3 monitoring network:

```bash
bash scripts/connect-trl4.sh
# http://filantropia-nextcloud:80 · http://filantropia-ml:8501 on compose_city_internal
```

**TRL5** (`wera-ss-pt-tv-1`) — use `docker-compose.yml` + `docker-compose.trl5.yml`,
backup first (`../docs/ops/TRL5-BACKUP.md`), then gates in
`../docs/mvp/MVP-7-GATES-TRL5.md`. Cold start: `scripts/setup-trl5.sh`.

Network joins are Docker state — re-run `connect-trl4.sh` after stack recreation.
Token handling: `../warp.md`.

## Public API (external consumers)

Token-authenticated read-only endpoints under
`/apps/filantropia_solar/api/public/v1`:

| Endpoint | Method | Description |
|---|---|---|
| `/stations` | GET | Public stations (Planned + Running lifecycle; not virtual/dataset-only) |
| `/dashboard` | GET | Station count, total capacity, locations |
| `/estimate` | POST | ML estimate for `{latitude, longitude, capacity_kwp, location?}` |

Auth: `Authorization: Bearer <token>`. The token is generated by
`scripts/setup.sh` (Nextcloud app config `public_api_token`) and exported to
`../../SolarSeed-v3/.secrets/filantropia_public_api_token` (mode 600).
Requests without a valid token receive 401.

## Authenticated API (app frontend)

Under `/apps/filantropia_solar/api/v1` (Nextcloud session + CSRF):

- Installations CRUD: `GET/POST /installations`, `GET/PUT/DELETE /installations/{id}`, `POST /installations/{id}/export`, `POST /installations/restore-dashboard`, `GET /installations/{id}/stats`
- Energy: `GET /installations/{id}/readings`, `GET /installations/{id}/stats`, `POST /installations/{id}/import`
- Dashboard: `GET /dashboard`, `GET /dashboard/savings`
- Predictions: `GET /installations/{id}/forecast`, `POST /installations/{id}/predict`, `POST /predict/period`
- Admin (admin-only): `/admin/bootstrap`, `/admin/stations*` (CRUD), `/admin/dataset/reimport`, `/admin/ml/cache*`, `/admin/ml/model*`, `/admin/ml/train*`, `/admin/settings`

See `appinfo/routes.php` for the canonical list.

## Requirements

- Nextcloud 28, 29, 30, or 31
- PHP 8.1–8.4
- Node.js 18+ and Docker (for development)

## Manual installation (existing Nextcloud)

```bash
cd /path/to/nextcloud/apps
git clone https://github.com/WeRaDev/FilantropiaSolar.git filantropia_solar
cd filantropia_solar/nextcloud-app
npm install
npm run build
cd /path/to/nextcloud
php occ app:enable filantropia_solar
```

Primary repository is on Gitea (self-hosted); GitHub is a mirror.

## Development

```bash
npm install
npm run watch    # development build with watch
npm run build    # production build (required after source changes)
npm test         # vitest
npm run lint     # eslint
```

Component conventions: Vue SFCs stay under ~400 lines; shared logic lives in
`src/composables/` (`useAnalyticsStats`, `useAnalyticsExport`,
`useAnalyticsDateRange`, `useEnergyChart`); the analytics modal composes
`src/components/analytics/*` subcomponents.
